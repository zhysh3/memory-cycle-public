# memory-cycle-public

一个用于判断**存储行业（DRAM / NAND）周期位置**的 Claude Skill。

输入一句话（比如「内存还要涨多久？」），它会自动检索公开数据，按固定规则判四个灯，输出一份带日期、带来源、可与上一期对比的周期评估简报。

## 它做什么

追踪四个基本面指标，全部机械判定，不允许手动调整：

| 指标 | 性质 | 判什么 |
| --- | --- | --- |
| 1. Memory Capex 温度 | 远端 | 三星、SK hynix、Micron、SanDisk 的资本开支合计同比 |
| 2. DRAM 合约价环比 | 近端 | TrendForce 一般型 DRAM 合约价 QoQ，辅以现货 |
| 3. 中国存储产出 | 远端（价格破坏时影响近端） | CXMT 产能、YMTC 出货与份额、定价性质 |
| 4. 全渠道库存周数 | 近端，最硬的前瞻指标 | 原厂 / OEM / 渠道 / 云厂商库存周数与交货周期 |

由此得到：

- **近端评级（未来 3-6 个月）** = 指标 2 + 指标 4
- **远端供给风险（12 个月以后）** = 指标 1 + 指标 3
- **周期位置**：Upcycle 加速 / 见顶窗口 / Downcycle 前段 / Downcycle 后段 / 底部反转

## 设计原则

- **只用行业基本面数据**：价格、产能、Capex、库存、出货、交期。不涉及股价、市值或任何资本市场走势。
- **永远用最新数据**：同一数据点有多个来源时，按发布日期最新的取；实测优先于预测。
- **标口径和日期**：合约价与现货、$/Gb 与模组价、bit 份额与营收份额、实测与预测，都要写明。
- **不编数**：取数顺序全部走完仍没有数据，才写「数据不足」，并标可信度低。
- **可对比**：每次运行会自动找上一期报告，列出哪个灯变了色、哪个数字变了。

## 安装

**Claude Code / 支持 Skill 的客户端**

```bash
git clone https://github.com/zhysh3/memory-cycle-public.git
cp -r memory-cycle-public ~/.claude/skills/
```

**Claude 网页版和 App**：把整个目录打包成 `.skill` 文件后上传。

## 使用

```
内存还要涨多久？
接下来半年存储周期怎么走？
现在存储行业是 Upcycle 还是 Downcycle？
```

## 维护

`SKILL.md` 里有两张需要随财报滚动更新的基准表：

- **Capex 上年实际值基准表**（指标 1）：某家公布新的财年实际值后，往前滚动。
- **中国产出基准表**（指标 3）：CXMT / YMTC 产能与份额。

技能运行时如果发现新数，会在报告里给出「基准表需更新」提示。
